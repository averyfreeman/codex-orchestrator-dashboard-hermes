The Hermes-centered Codex Orchestrator Dashboard gives an operator one view of Codex app-servers and fleet sync, Herdr sessions, Treehouse worktrees, and reviewed multi-worker runs. Hermes drafts dependency-aware plans; the operator reviews prompts and starts each run, and Codex app-server hosts execute the workers. The dashboard also supports direct Codex controls, Codex sync, named Herdr sessions, and a guarded daemon start when a host is down.

The **dashboard is a self-hosted Next.js application**. The public GitHub Pages site is a separate static operator and maintainer guide; it has no fleet inventory, credentials, or live control API.

## What runs where

The browser talks to the self-hosted Next.js gateway over private LAN or overlay interfaces. The gateway reads bounded host metadata over local probes or strict SSH, and starts host-scoped Codex app-server workers only after the operator reviews and starts a plan. SSH uses the configured route order. Private host inventory and SSH keys stay on the gateway host.

For deployment, GitHub Pages builds only this documentation tree. Next.js request-time route handlers, streaming turns, and local file-backed telemetry remain on the operator’s machine. See [why the app is self-hosted](./maintainers/architecture/#deployment-boundary).
